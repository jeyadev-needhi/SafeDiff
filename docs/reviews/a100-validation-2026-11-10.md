# Earlier SafeDiff A100 validation snapshot

On November 10, 2026 (Asia/Shanghai), an earlier sealed SafeDiff snapshot passed
validation on one NVIDIA A100-PCIE-40GB. That snapshot included additional
routing changes. The current standalone delivery retains the A/B decoders
and the legacy blockwise fix. The 36 tests, 24 calls, and 16 comparisons
below apply to the earlier source archive. The runner used PyTorch 2.12.0+cu130,
CUDA 13.0, Transformers 4.49.0, BF16, and 32 SDPA attention modules.
It used the local GSAI-ML/LLaDA-8B-Instruct checkpoint at revision
`08b83a6feb34df1a6011b80c3c00c7563e963b07`. The validation driver hashed all
six weight shards and matched their digests to the public LFS SHA-256 values.
`model-verification.json` records the shard and checkpoint metadata hashes.

## Results

- **36 CPU and mock tests passed** on the remote environment.
- **24 real-model generations passed**, with 12 fixed calls and 12 mixed-order
  calls through the adaptive runner. All calls preserved the 256-token canvas,
  reported the expected preset and observed forward count, and finished
  with zero residual MASK tokens. The two benign prompts asked for a short
  arithmetic answer and a one-sentence explanation of the blue sky.
- **16 comparisons passed.** For each prompt, fixed and mixed-order calls
  matched token-for-token and in forward count for every plan/policy slot.
  A NORMAL matched B SAFE at threshold 0.9. All arms used identical input
  and prompt-token hashes. Mixed-order routing used recorded Guard verdict
  fixtures through the actual adaptive runner.
- **Two original-model SAFE comparisons passed.** On both prompts, Plan A
  SAFE matched the pinned vanilla decoder running on the original checkpoint
  model for the prompt prefix, all 256 generated tokens, and all 256 forwards.
- **One legacy blockwise comparison passed.** On the arithmetic prompt with
  `steps=64`, `gen_length=64`, and `block_length=32`, the repaired legacy
  decoder and the official blockwise decoder produced identical tokens in
  64 forwards. The second block stayed masked during the first block, and
  the completed first block stayed stable during the second.

and the 256-token generation budget. For a fresh standalone check, use the
command in the configuration guide. `source-verification.json` identifies the tested
archive based on PR #7 head `2999719922f25c42fc7f691e469d332647591bf5` and
records verification of all 68 packaged files and two parity scripts. The

The evidence bundle contains `summary.json`, the raw `calls.jsonl`,
`original-safe-parity.json`, `cpu-tests.log`, `run-status.json`, and the
source and model verification records. The download independently matched
all 11 manifest entries by size and SHA-256. The evidence archive SHA-256 is
`e5656a46a1f61c53270bd5f562699d4cc977b53631705257cef1cfbdf4f29022`.

This run established integration and exact parity for the tested inputs
on the archived snapshot.
The first A FAST arithmetic call took 2.575 seconds of generation despite
an already loaded model, while its identical mixed-order repeat took 0.155
seconds. This first-call overhead and fixed order limit any latency
interpretation. A comparative speed study, live QwenGuard classification,
response safety, and full-task SAFE quality require separate measurements.
