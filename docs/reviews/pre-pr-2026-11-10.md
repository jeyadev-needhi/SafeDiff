# SafeDiff integration review

The upstream review covers the LLaDA generation and QwenGuard routing path on
`jeyadev-needhi/SafeDiff` at `675d64020dc4004fed1a16476f0d837a5312f87f`. The
local delivery contains the blockwise fix and a standalone Plan A and Plan B
backend based on PR #7 at `2999719922f25c42fc7f691e469d332647591bf5`. The
original routing and experiment scripts remain at their upstream versions.
The review covers the interfaces below and leaves the other SafeDiff defenses
and their experimental validity outside its scope.

## Upstream main findings

| Priority | Finding and trigger | Delivery status |
|---|---|---|
| P1 | **The active generation block expands over later blocks.** The block span always expands to the first and last remaining MASK. With an unmasked input, generation length 64, block length 32, and 64 scheduled steps, the first block spans all 64 slots and plans two transfers per round. If every selected token replaces a MASK, the second block still runs 32 forwards with zero transfers. [Block selection and quotas](https://github.com/jeyadev-needhi/SafeDiff/blob/675d64020dc4004fed1a16476f0d837a5312f87f/utility/generate_function_llada.py#L212-L245) · [Forward and transfer loop](https://github.com/jeyadev-needhi/SafeDiff/blob/675d64020dc4004fed1a16476f0d837a5312f87f/utility/generate_function_llada.py#L247-L339) | Ordinary denoising is limited to the active block and skips forwards with no eligible transfers. The existing refinement and whole-sequence settings are preserved. |
| P1 | **The runner ignores QwenGuard's decision.** The original runner reads `risk_level` or `label`, defaults to zero, and overwrites `adaptive_policy`. A smoke row with `source_label`, `risk_tier`, `qwen_guard=Unsafe`, and `adaptive_policy=SAFE` therefore runs FAST. With the Week 10 builder's binary WildJailbreak or XSTest label, an unsafe row has level 1 and the legacy oracle runs NORMAL. [Oracle selection and overwrite](https://github.com/jeyadev-needhi/SafeDiff/blob/675d64020dc4004fed1a16476f0d837a5312f87f/analysis/adaptive_acceleration_prototype.py#L22-L50) · [Week 10 labels](https://github.com/jeyadev-needhi/SafeDiff/blob/675d64020dc4004fed1a16476f0d837a5312f87f/analysis/build_safety_eval.py#L30-L92) | Deferred for the controller owner. |
| P1 | **The QwenGuard rule uses evaluation labels.** A `MEDIUM` row always gets NORMAL, including when QwenGuard returns Unsafe. The smoke builder assigns MEDIUM using the known benign medical label. The original verdict parser also accepts text prefixes such as `Safety: Safeguard` as Safe. [Original parser and route](https://github.com/jeyadev-needhi/SafeDiff/blob/675d64020dc4004fed1a16476f0d837a5312f87f/analysis/run_qwen_guard.py#L47-L81) · [Smoke tier construction](https://github.com/jeyadev-needhi/SafeDiff/blob/675d64020dc4004fed1a16476f0d837a5312f87f/analysis/prepare_eval_smoke.py#L61-L83) | Deferred for the controller owner. |
| P1 | **The original generator drops the smoke prompt.** Its field picker omits `text`, the smoke builder's prompt field. Passing an annotated smoke row through the original runner produces an empty user message. Conversely, the original QwenGuard annotation script reads only `text`, while the Week 10 builder emits `prompt`. [Generation field picker](https://github.com/jeyadev-needhi/SafeDiff/blob/675d64020dc4004fed1a16476f0d837a5312f87f/models/jailbreakbench_llada.py#L383-L397) · [Original Guard input](https://github.com/jeyadev-needhi/SafeDiff/blob/675d64020dc4004fed1a16476f0d837a5312f87f/analysis/run_qwen_guard.py#L63-L64) | Deferred for the controller owner. |
| P2 | **A missing refined prompt still gets a pair score.** The legacy script builds a detection tail for empty refined text and compares two hidden-state forwards. On single-prompt data this can report a template-attack result without a real comparison. Once `text` is read correctly, that score compares a real prompt to an empty one. [Pair detection](https://github.com/jeyadev-needhi/SafeDiff/blob/675d64020dc4004fed1a16476f0d837a5312f87f/models/jailbreakbench_llada.py#L498-L525) | Deferred for the controller owner. |
| P2 | **The prototype timing mixes different costs.** The runner passes 16/32/64 scheduled steps to the same legacy generation script with no cache or confidence-threshold controls. Each nonempty tier launches a fresh process and reloads the model. Its outer timer includes those loads, extra hidden-state probes, and result I/O. QwenGuard runs separately. The original defaults are temperature 0.5 and CFG 0.1, with conditional and unconditional inputs evaluated together. [Runner invocation and timing](https://github.com/jeyadev-needhi/SafeDiff/blob/675d64020dc4004fed1a16476f0d837a5312f87f/analysis/adaptive_acceleration_prototype.py#L70-L101) · [Model loading](https://github.com/jeyadev-needhi/SafeDiff/blob/675d64020dc4004fed1a16476f0d837a5312f87f/models/jailbreakbench_llada.py#L439-L455) · [Generation defaults](https://github.com/jeyadev-needhi/SafeDiff/blob/675d64020dc4004fed1a16476f0d837a5312f87f/models/jailbreakbench_llada.py#L37-L83) · [CFG forward](https://github.com/jeyadev-needhi/SafeDiff/blob/675d64020dc4004fed1a16476f0d837a5312f87f/utility/generate_function_llada.py#L261-L274) | Deferred for the controller owner. |

The reported single-prompt 64-versus-53 forward comparison remains a smoke
observation. The report needs its exact code revision, entry point, checkpoint,
and parameters before it can be attributed to an implementation. A forward
call count alone does not measure latency or safety.

## Standalone delivery and validation

- Plan A selects ALL8, Fast-dLLM dual-cache 0.9, or original uncached LLaDA.
  Plan B keeps the Fast-dLLM dual-cache decoder and selects 0.7, 0.8, or 0.9.
  The standalone entry points record the supplied plan, policy, resolved mode,
  and generation settings. `SAFE` is a policy name. Token confidence thresholds
  control token acceptance, and response safety still needs evaluation.
  [Configuration guide](../acceleration.md)
- The pinned Fast-dLLM warmup can revisit a MASK
  left by a previous block because it masks only positions after the current
  block. That vendor behavior remains part of the measured preset. Residual
  output masks are recorded. [Pinned decoder](../../acceleration/vendor/fastdllm.py#L230-L263)

The delivered standalone code passed 14 CPU and mock tests and all six GPU
calls on one GSM8K test question. The repaired 64/32 legacy decoder matched
the official blockwise output and forward count on the same prompt. The
checkpoint's original model and sampler also reproduced the exact A SAFE
output, including its wrong answer.
[Current GSM8K validation](gsm8k-validation-2026-11-10.md)

An earlier November 10 snapshot passed 36 CPU and mock tests and all 24
pretrained generation calls and 16 comparisons on an A100. Both Plan A SAFE
prompts matched the original checkpoint model, and one 64-token case with
32-token blocks matched the official blockwise decoder. That snapshot
contained additional routing changes and used fixed Guard verdicts. Its
receipt applies to the earlier sealed source. [A100 evidence](a100-validation-2026-11-10.md) · [Historical results](../benchmarks/plan-options-2026-11-10.md)
